## Commercial amount and states

Native CRM bookings only. Owner chooses deposit_percent50(default)|100. Server freezes the agreed services/extras + travel fee minus agreed discounts in one FinancialRevision, USD cents. Principal = ceil(total×percent/100); customer_fee = round-half-up(principal×3/100); payable = principal+customer_fee. Browser amounts are hints, never authoritative. Show all three before paying, same fee for every actually enabled Stripe method. No Stripe surcharge feature or later method-dependent addition. Original service total/deposit-target principal stays separate; receipt keeps real gross, reporting/payment balance credits only verified principal, reports fee separately. Never treat3% as extra package sale or principal credit.

Pending payment uses a separate `quick_stripe_bookings` record and lease-backed inventory group, **not a fake LedgerEntry, owner verification or paid QuickBookingRecord**. The paid hold V1 receipt FK must not be satisfied by a dummy receipt or silently weakened. Introduce explicit versioned unpaid backing in the common inventory protocol; freeze48h created_at/expires_at and24h reminder_at once at durable link/lease creation. Retries, new checkout sessions, reading/copying the link or a reminder never renew the lease.

States: awaiting_payment, processing, deposit_received, expired_unpaid, paid_needs_review, cancelled/review_required. Deposit_received means actual commercial payment received; **staff/equipment/driver capacity is not invented** and Event.status stays draft until existing complete operational confirmation. On verified payment, real gross receipt and principal/fee evidence append once, create/bind the genuine paid quick-book linkage, consume unpaid backing into paid costume hold without duplicate reservation. Same portal continues to details/contract. Do not auto mark capacity_reserved without staff review.

Date/time held is that party's pending operating slot, not exclusive ownership of a whole calendar day or a promise of full crew availability. Staff stays for later. Unknown buffers use known costume window + review_required/timing_unknown, preserving null. No costume recipe means a date/payment lease without fake costume inventory. Failed initial inventory allocation is explicit blocked; do not create a payable promise for unavailable capacity.

## Backend slice S1 freeze — money and absolute deadline terms (contract before code)

`App\Services\Booking\QuickStripeTerms` is an internal immutable value, not an HTTP endpoint or inventory/payment proof:

- `freeze(mixed $totalCents, DateTimeImmutable $createdAt, mixed $depositPercent = 50): self`. Only integer cents1..99_999_999, percent exactly integer50/100. Principal ceil, fee half-up using integer arithmetic; reject payable above Stripe's8-digit amount limit (99_999_999). This is a provider integration bound, not a new package/owner price. No float or numeric-string coercion. Caller must first lock/validate the actual FinancialRevision and use its total; never trust browser totals.
- `snapshot(): array` closed V1 `{schema_version:1,total_cents,deposit_percent,principal_cents,customer_fee_cents,payable_cents,currency:USD,created_at:int,reminder_at:int,expires_at:int,sha256}`. Dates are UTC epoch seconds, fixed at original agreement creation, reminder+86400 and expiry+172800 absolute seconds across Houston DST. Explicit field list only. sha256 covers all preceding fields via MutationKey::hash; no whole-model hashing. The later public projection converts these to the ISO fields above.
- `restore(array $snapshot): self` rejects missing/extra/wrong-type fields, invalid dates/amounts, recomputed deadline/rounding differences and hash mismatch. Restores original creation time, never now; no retry renewal. A self-consistent hash is not an authorization/signature or independent financial provenance check. Bind to immutable agreement/history/current event separately in S2.
- `checkoutExpiresAt(DateTimeImmutable $now): int` → min(frozen expiry,now+23h). Reject now before original creation or if less than31min remain, rather than inventing a longer lease/session. This determines a new frozen provider request once, not parameters to recompute on an unknown-response retry. S2 persists/replays the exact provider request before network.

S1 has no storage/migrations, routes, outbound call, enabled flag, portal grant, allocation, reminder dispatch, webhook or receipt. Tests must cover odd cents/fee half-cent ties/provider bounds, strict types, snapshot corruption, DST absolute48h, replay without renewal, and31min boundary.
