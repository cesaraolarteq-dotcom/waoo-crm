## Required: #59 pagination (P2)

`app/Filament/Pages/Leads.php:58` always requests `per_page=50` without forwarding a page. `rows()` discards the paginator, and `resources/views/filament/pages/leads.blade.php` has no navigation. The counts can show 51 new leads while the oldest lead is unreachable; `?page=2` still renders page 1. The same problem affects the historical `Todos`/`Reservados` views as records accumulate.

Use Livewire pagination (or equivalent bounded previous/next navigation), pass its page to `ReadLeads::index`, retain paginator metadata, and reset page when the status changes. Do not remove the service's 50-record bound or load every lead. Add a 51-record test reaching the omitted record through the actual page controls, plus filter-change page reset. The opt-in diagnostic below proves that the backend already returns that record on page 2.

## Required: #54 recipient validation (P2) and warning lifecycle

`app/Filament/Support/ContactLinks.php:11` still removes every nondigit. `(346) 555-0100 ext 123` becomes the different international recipient `3465550100123`; `DO NOT TEXT 346-555-0100` and eleven zeroes also produce links. Because the prefilled message carries a bearer portal link, reject ambiguous/free-text/extension inputs instead of guessing a recipient. Keep conventional US formatting support and explicit supported international numbers; do not infer a foreign country from a long stripped string. Add regression tests with invalid examples and valid formatted US/international cases.

Both `quick-booking.blade.php:7` and `event-contract.blade.php:18` register anonymous global `beforeunload` listeners for transient Alpine components without teardown. The code should describe copied/opened state rather than claim delivery: opening a messaging app cannot establish that the owner sent the message. Use “Abrir SMS con el mensaje”, matching WhatsApp. Verify cleanup/remount and both platforms in a browser; PHP rendering tests do not prove OS-app behavior.
