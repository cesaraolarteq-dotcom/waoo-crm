# Portal link switching — PR107 correction, 2026-10-21

Contract before code. No new endpoint, scope, token, provider, message, deployment or business policy. Existing POST `/portal/api/session` remains the sole booking/quote exchange: `{token}`; response `{csrf_token,expires_at,scopes}`; real session ID and CSRF rotation, expiry/revocation/transport/CSRF checks unchanged. Tips keep their separate raw-fragment exchange and cookie.

A booking/quote link must work both on first document load with an old authenticated cookie and when opening it changes only the current page's fragment (`hashchange`, without another HTTP document load). Use one shared layout handler, including the landing page, not two independent exchanges. Token stays in fragment then transient memory/POST body only; remove it from the address/history immediately. Never put it in query/localStorage/sessionStorage/logs or interpolate it into HTML.

Before exchanging, hide and make the old main content inert. No details, signature, payment or other old-party action is submitted as part of switching. A successful exchange redirects to `/portal/quote` for quote.read, otherwise `/portal`, retaining the requested query/language; return URL/query does not grant access or prove payment.

Serialize rapid switches. Keep only the latest queued fragment, send no simultaneous exchanges with an obsolete CSRF token, and use the token returned by each successful exchange for the next queued exchange. Redirect only after the latest requested valid exchange succeeds; never briefly render an earlier party. A failed/invalid exchange removes the old forms and shows the existing bilingual unavailable-link copy. A later valid link can be opened from that same page. If the latest fragment is malformed, an earlier in-flight response must not restore/redirect to the older party. No automatic charge/signature/data submission or activation.

The real backend already rotates CSRF on exchange; a page open before switching cannot POST its previous details into the new party (419). Do not weaken that guard, auto-resubmit an old form with the new CSRF, fabricate a PortalContext or create another session endpoint. Current owner sign-in prohibition remains unchanged.
