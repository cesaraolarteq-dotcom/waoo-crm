## Outbound boundary

- `WAOO_MAIL_DELIVERY_ENABLED=false` is a new independent master hold. `MailDeliveryGate::enabled()` reads strict boolean configuration; there is no readiness percentage, timer, UI or command that turns it on automatically. All added placeholders stay disabled/empty. Claude must keep the host holdOFF too; this repository work does not prove its current environment.
- Laravel `MessageSending` listener returnsfalse while held, including framework SMTP/Resend mail (e.g. password reset); it neither sends nor logs a substitute message body. Existing framework `MAIL_MAILER` is not switched. The application MailTransport binding stays Disabled unless the master gate, sandbox_mail, sandbox environment, provider=resend, key and explicit sender/reply-to configuration all permit the adapter. Direct adapter.send rechecks these gates before any HTTP.
- `ResendMailTransport implements MailTransport`: fixed HTTPS POST https://api.resend.com/emails, bearer key from services.resend.key / RESEND_API_KEY; configured from name/address and reply-to; one recipient, unchanged html/text/subject. No arbitrary endpoint, redirects, SDK/dependency, attachments, real key lookup, connection probe or automatic retry. connect2s/total5s. Idempotency key namespaced `waoo-outbox:<message-id>` so other local tables cannot reuse a provider key. Require an existing matching encrypted outbound envelope/recipient, active enrolled owner allowlist, no bounce suppression; exact outgoing content cannot be supplied by an arbitrary caller. Returns provider=resend plus UUID id, meaning accepted, never delivered.
- 429/5xx/timeouts/untrusted provider response return a generic transport failure. Existing claim-before-provider/outcome-unknown semantics remain: no automatic resend, including after the provider24h idempotency retention window. HTTP statuses do not justify overriding the unknown-outcome protection. Requests use mocks only in tests.
- QuickPaymentNotification IDs are a separate identity space and currently do not persist provider delivery IDs. Resend dispatch for this parallel path stays blocked before claiming a notice, even if later sandbox gates are opened. No misleading sent/unknown marker from attempting an unsupported path. A dedicated future receipt/suppression integration is required before enabling that channel; fake-transport regression behavior remains supported. This is a recorded readiness gap, not silently declared complete.

## Authenticated inbound evidence (independent of sending)

POST /webhooks/resend, stateless, default-OFF `WAOO_SANDBOX_RESEND_WEBHOOKS=false`, local/testing/staging and HTTPS only. Signing secret `WAOO_RESEND_WEBHOOK_SECRET`, whsec_ prefix + strict base64 decoded16..128bytes. Max64KiB raw body, rate120/min. Preserve raw body (exclude global input normalization); authenticate before JSON parsing. Header `svix-id`, decimal `svix-timestamp` within±300s, space-separated `svix-signature` entries `v1,<base64 HMAC-SHA256>`. Signed bytes are `id.timestamp.rawBody`, using decoded signing secret. Constant-time comparison; accept one matchingv1 among rotation signatures. No outgoing API call on webhook receipt.

Processed types: email.delivered, email.bounced, email.complained. created_at is the event timestamp with explicit offset (including1..9 fractional digits; exact timestamp hash preserves sub-second replay identity independently of database precision) and <=now+5min. Require data.email_id (UUID) and data.to exactly one valid recipient. Provider ID must match an already committed Resend outbound send receipt, message environment sandbox and exact encrypted intended recipient/hash. Early/missing receipt503 for provider redelivery, wrong recipient422; no fabricated sent receipt. Other authenticated event types are acknowledged without mutation, not treated as a bounce. email.bounced is terminal provider failure; delay events never suppress.

New narrow `RecordMailDelivery::authenticatedResend` uses the receiver gate rather than sending gate, so genuine late delivery/bounce evidence can be retained while the master hold isOFF. Reuse normalized immutable event keys, replay intent hashes, complaint/bounce precedence, no auto-unsuppression or resend. Persist no raw provider payload, subject, addresses, headers, body, key or signature. No new table/migration is required for the supported outbox path. Different content/outcome/time under the same provider event ID409; exact retries idempotent. Only aggregate status codes are public; private,no-store for successful and failed webhooks.
