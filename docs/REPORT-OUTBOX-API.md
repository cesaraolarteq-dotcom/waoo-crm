# JOBS-01 / REPORT-A — durable local preview outbox

Contract before code. Sandbox only, **no email**, no production adapter, scheduler or queue dispatch. A local DB receipt represents a simulated preview, never recipient delivery. This slice proves retry/lease mechanics for later reviewed integrations.

`EnqueueReportPreview::execute(User $actor, int $snapshotId): ReportPreviewDelivery`
`ProcessReportPreview::execute(int $deliveryId): ReportPreviewDelivery`
Namespace App\Services\Reports\Outbox. Owner-only POST `/admin/api/reports/snapshots/{snapshot}/preview-delivery` returns201, private/no-store. Both finance sandbox and new sandbox_report_outbox flag (default false) required, plus owner/2FA. Processing is an internal worker path with the same sandbox gates. No client transport/copy changes.

Outbox table report_preview_deliveries: unique snapshot_id (company-wide, no actor key), environment=test, recipient fixed sales@waooparty.com, payload_sha256, status pending|processing|completed|failed|cancelled, attempts, available_at, lease_until/token, completed_at, last_error_code and timestamps. Hidden lease token, never serialized. Immutable report remains source of exact payload bytes; worker verifies source/hash/recipient/environment before recording a preview. No body/exception text in logs. Separate report_preview_receipts has unique delivery_id and unique stable idempotency_key, payload hash and opaque receipt reference; **no network or mail call**.

Row-lock claim increments attempts, issues a random token and90s lease, then commits before calling the local database transport. No second claimant while lease valid. Expired leases may retry. Token and lease expiry fence success/failure acknowledgment, so an old worker cannot overwrite a newer claim. Same stable provider key on every attempt; DB transport inserts/returns one durable local receipt even after a crash between transport and acknowledgment. Max5 attempts; transient backoff60/120/240/480s (capped900), terminal failure after fifth. Invalid source is terminal payload_invalid. Last errors are fixed codes only. Audit enqueue/preview completion/exhaustion atomically with corresponding state; rollback leaves recoverable pending/leased work. No external exactly-once guarantee is claimed; any future real adapter must define its provider's idempotency retention and ambiguous-send handling first.

Dependencies: PreviewTransport::record(int deliveryId,string key,string payloadJson,string leaseToken):string; bound only to DatabasePreviewTransport. Test injection simulates transport failure/late acknowledgments without sending. Manual local command `reports:process-previews --limit=10` scans due pending/expired work, limit1–100, no scheduled registration. Local DB work must finish within lease; future queue timeout30 < lease90 < DB retry_after120, provider request timeout must be separately bounded if one is added. --max-time alone is not a request timeout. This command is not a production email sender.

Claude can display “Vista de prueba pendiente/completada/fallida”, attempts and fixed error code; no “correo enviado” label or Send action. Real provider, email HTML/copy approval, daily limits, bounce handling, scheduler overlap/alerting and activation remain later work. Owner does not need to provide credentials for this slice.

Cancellation and read-status extension: docs/REPORT-OUTBOX-CANCEL-API.md. Transport now requires the active claim token; keep the interface, processor, DB adapter and test adapters together. Cancelled tasks are terminal and are not rearmed by enqueue.
