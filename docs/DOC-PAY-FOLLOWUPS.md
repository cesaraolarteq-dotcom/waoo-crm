# DOC/PAY small follow-ups (API contract before implementation)

1. Terms allow only `{{client.first_name}}`, `{{client.last_name}}`, and `{{payments.balance_amount}}` (optional surrounding whitespace). No sections, raw fields, expressions, partials or other variables. Values come from the issued commercial/payment snapshot, are escaped once and never interpreted as templates. Original legal terms and their SHA-256 stay immutable; presented HTML/PDF freezes the resolved values. A change still requires a new owner-approved template version.
2. `SaveVariant::execute(User, array, ?int)` accepts optional nullable `long_description` (plain text, max 10,000 characters). Omission preserves existing content; explicit null clears it. New financial revisions copy it into each line; contracts use that frozen line, never live catalog text. Old revisions show no invented description. Customer PDF requirements get English labels; unknown custom roles use generic resource labels, without exposing internal codes or inventing capabilities.
3. `App\Services\Portal\RevokePortalGrant::execute(User $actor, int $grantId): PortalGrant` reauthorizes the owner, locks the same grant row used by signature acceptance, revokes and audits atomically. Repeating is safe, no duplicate audit; existing API response stays `{revoked: true}`. Existing scoped sessions fail immediately on next request. No reason or new endpoint required.
4. QuickBook / SubmitClientDetails are delivered on `codex/quick-booking-core` (source 1a5fbe3, head 078f819): see BOOK-QUICK-API.md. This integration preserves that delivery and Claude's 2074213 real portal. UI wiring/review remains Claude's responsibility.
