## Delivery boundaries

**A, first backend increment:** private bounded CSV upload, explicit column/format mapping, strict normalization, duplicate/conflict detection, preview/reconciliation, owner-only paginated reads and discard. Writes only import staging metadata/evidence and audit. Creates no customer, event, financial revision, ledger entry, capacity block, contract, grant or message. `ready` means structurally ready for owner review, never capacity available or imported. Claude can build upload/profile/preview against this contract; commit and capacity buttons remain disabled.

**B, separate detailed contract before code:** explicit per-project mapping/resolution and idempotent import into customer/event drafts with honest historical agreement/money provenance. **C:** imported-money-aware confirmation and future-event reconciliation/cutover gate using ordinary resource/transport/short-notice rules. No unimplemented import/capacity method or fake external Zelle receipt may be substituted. IMPORT-01 is incomplete until every future confirmed source project is accounted for and normal capacity has been reconciled. Archive/history belongs to IMPORT-02, not automatic scope expansion.

## Authorization and upload transport

- Fresh active owner + confirmed2FA on HTTP and direct services; existing web CSRF/private response/throttle protections. New `WAOO_SANDBOX_IMPORTS=false` requires local/testing/staging; production denied. Import A does not require finance/documents flags because it cannot write those domains. Staging transport requires HTTPS and secure cookies. No HoneyBook credentials, URL fetch, provider key or public endpoint.
- All mutations receive an explicit UUID `Idempotency-Key`. No server rotation on uncertain response. Same actor/key + exact normalized intent and file byte hashes returns the original result; another intent409. Receipt lookup precedes mutable-state checks, but discarded source data is never resurrected by replay. Transaction includes staging records/audit/receipt. A failed private file write or parse/audit failure cannot leave a readable partial batch; an unreachable private artifact may need cleanup after DB rollback. Cleanup failures remain visible/retryable rather than falsely reporting deletion.
- `StageHoneyBookImport::execute(User $actor,array $input,string $key): ImportBatch`; `POST /admin/api/imports/honeybook` multipart. Input `files[]` with explicit unique role `projects|customers|payments` and `file: UploadedFile`, plus `profile` JSON. Exactly one projects file; customers/payments optional. Files cannot be supplied as filesystem paths, URLs or preselected foreign batch IDs. UUID/hash does not authorize access without the owner checks.
- Technical defaults: CSV text only,5MiB per file,15MiB aggregate, projects2000 rows/customers5000/payments10000,100 columns/row,32KiB/cell. Enforce limits during stream reads, not after loading unbounded input. Reject NUL/binary/XLS/XLSX/ZIP/PDF and malformed quoting/encoding; no macros, formulas, links or external entities are evaluated. UTF-8 (optional BOM) by default; Windows-1252 only when explicitly chosen. Delimiter explicitly comma/semicolon/tab; no locale guessing. Headers/rows with ambiguous structure fail with file/row/field codes, never a raw client-containing exception dump.
- Profile freezes a schema version, source-role column map **by zero-based column index**, declared date/money formats and explicit source-status map. Duplicate header text is not guessed. File preview shows indexed header names so Claude can offer selectors. No automatic customer merging, package mapping, status interpretation or timezone inference from arbitrary text. An unrecognized status is review, never assumed confirmed.

## Profile input and the simple mapping flow

`profile` has `schema_version:1`, fixed `timezone:"America/Chicago"`, `encoding:"utf-8"|"windows-1252"`, `delimiter:","|";"|"\\t"`, `date_format` from a closed supported list (`Y-m-d` or `m/d/Y` initially), `money_format:"usd_dot"` (decimal point, optional comma grouping validated in groups of3), `columns` maps by role, and `status_map`/`payment_state_map` with explicit source strings mapped to the declared canonical states. Other formats/keys reject422; do not guess. Source strings remain case-sensitive unless a future profile version explicitly defines normalization.

Example `columns.projects = {"project_id":0,"project_status":1,"customer_name":2,"event_date":3,"start_time":4,"total_amount":5,"paid_amount":6,"balance_amount":7}`. Each value is a zero-based column index, never a browser-calculated amount. Joins use the role fields above. `status_map` canonical keys are confirmed/cancelled/other; payment keys received/refunded/pending/void. Unmapped source values remain review conflicts, never default received/confirmed.

For an unfamiliar export, first upload may use empty column maps. The batch returns indexed headers and `needs_review`; unknown data is not marked ready. Then `ProfileHoneyBookImport::execute(User,int batchId,array $input,string $key): ImportBatch`, `POST /admin/api/imports/honeybook/{batch}/profile`, receives `expected_version`, `expected_preview_sha256`, and complete profile. It reuses that batch's private immutable source bytes, avoiding another user upload. It serializes against discard using the batch row, advances the batch version and regenerates the current staged rows/reconciliation/hash. Old preview hashes become stale; preserve profile/hash/count audit history without unused source cells. Profile changes never edit the source file, reach committed domain data or silently reuse an uncertain UUID for a different profile. A fully declared profile can be supplied on the initial upload to skip this second step. B must refuse reprofiling any committed domain linkage until its explicit change/reconciliation contract exists.

## Normalized source contract

The parser handles only mapped fields. Preserve exact private file byte hashes and source row numbers; store only necessary normalized fields, not unused columns or raw rows in logs. Missing is null, never zero or empty as a substitute. Keep original necessary source strings alongside normalized values for owner review.

| Role | Canonical mapped fields |
| --- | --- |
| projects (required) | project_id, project_status, customer_id?, customer_name?, customer_email?, customer_phone?, title?, event_date, start_time, start_choice?, end_date?, end_time?, end_choice?, duration_minutes?, address?, postal_code?, package_text?, total_amount?, paid_amount?, balance_amount?, travel_amount?, contract_reference? |
| customers (optional) | customer_id, customer_name, customer_email?, customer_phone? |
| payments (optional) | project_id, payment_id?, amount, state, received_at? |

`?` denotes optional source data, not permission to fabricate it. Project ID is required, opaque/case-sensitive and bounded255; never use a spreadsheet row number as a cross-file/business identity. Unknown customer identity, package, end time, money or route data yields `needs_mapping`, not guessed values. Repeated same-name/different-phone customers never merge. Matching email/phone produces explicit hints only; even exact contact matches need an explicit existing-customer choice at domain commit.

Houston dates use the shared ChicagoTime resolver. Profile declares the source date format; canonical representation is `YYYY-MM-DD` + local `HH:mm` + optional explicit CDT/CST occurrence. DST gaps/ambiguous hours without a choice yield a per-row review error. If both end time and duration exist they must agree; if neither exists the row needs mapping. Never infer party duration from the current catalog. Original source date/time and resolved UTC window remain distinguishable. Same-day vs next-day end is explicit; do not silently roll backward times into tomorrow.

Technical normalization limits: duration1–10080 minutes; monetary magnitude at most9,999,999,999.99 USD per source value. `usd_dot` accepts an optional leading `$`, ordinary decimal point and correctly grouped commas; only balance may carry a leading minus. Negative payment amounts require review rather than inferred refund semantics; positive refunds need the explicit refunded state. Explicit `start_choice`/`end_choice` columns contain `cdt` or `cst`; optional `end_date` uses the same declared format. `received_at` accepts an explicit-offset ISO timestamp only; a missing date remains unknown. These parsing bounds do not invent source values.

Money uses strict decimal parsing to integer USD cents: explicit currency/grouping/decimal profile, no floats, scientific notation, rounding, parenthesis/minus reinterpretation or blank→0. Signed refunds/voids/pending payments require a declared state mapping; they are not positive received money. Unknown payment state/absent required payment identity is review. Existing source totals win over current catalog prices. Travel amount is recorded source evidence, never recalculated from a guessed ZIP or copied from a current package price.

If source projects contain paid/balance and a separate payments file, reconcile both independently; never add project-paid to summed transactions. Aggregate project-paid without itemized payments remains an **aggregate source amount**, not invented transaction rows or invented receipt dates. Known `total − paid` must reconcile with known balance; distinguish overpayment from missing data. Unknown/mismatched/inconsistent totals remain visible conflicts. Package/current-price mapping is operational only and cannot reprice historical agreements or allocate an unknown breakdown across services.

Source-status profile explicitly maps confirmed/cancelled/past-relevant states. Past events and cancelled source projects are listed as skipped with reason (no draft/resource writes). Unknown date/status blocks a ready classification. Snapshot the preview's server comparison instant and local date; future/past classification is rechecked at later commit, not trusted from a client clock.

## Staging data, preview and lifecycle

- `import_batches`: actor, version/status, profile/hash, source metadata/hashes, received_at, reconciliation/preview SHA-256, private artifact references, cleanup state. Artifact paths are hidden/guarded. Initial states prepared|needs_review; discard/cleanup_pending/discarded are explicit. Later committed/partially_committed belong to B. Expiration/retention schedule needs its own approved policy; no silent automatic deletion interval invented.
- Private `import_files` keyed by batch/role, immutable original filename metadata (display escaped, never a storage path), byte hash/count, selected profile and parse metadata. Use generated private filenames, no public storage link or raw file download route. Metadata is not permission to reveal file contents outside owner APIs.
- `import_rows`: batch/role/source row and project/customer/payment keys, version, necessary normalized source, validation/conflict reasons, status ready|needs_mapping|conflict|skipped, duplicate hints and preview hash. A source upload is never modified in place. A re-upload creates a new batch with the same project identities/content hashes for comparison; identical bytes/profile under a new UUID reuse the existing active batch. Discarded metadata can remain a non-PII tombstone, never restore purged source data implicitly.
- Within a file, duplicate project/payment keys conflict rather than silently selecting the last row or crediting twice. Cross-file references must resolve unambiguously. Source project identity remains unique for eventual domain linkage across all batches; byte hash alone is not business idempotency. Later source edits must show a new revision/diff; no history, received money or confirmed/signed event may be overwritten.
- `ReadHoneyBookImport::index(User,array): LengthAwarePaginator`; `GET /admin/api/imports/honeybook` page>=1/per_page1–50, optional allowed batch status; newest first, metadata/counts only.
- `ReadHoneyBookImport::show(User,int batchId): array`; `GET /admin/api/imports/honeybook/{batch}` returns `{batch, files, reconciliation}` metadata + explicit known/unknown/conflict counts and totals. No artifact path/raw CSV, token, unused source columns or SQL exception. Every total includes `known_count`, `unknown_count`, and conflict count; do not silently sum known rows and label the result complete. Groups retain source status and project identities; cancelled/past are not silently removed from source counts.
- `ReadHoneyBookImport::rows(User,int batchId,array): LengthAwarePaginator`; `GET /admin/api/imports/honeybook/{batch}/rows`, page/per_page same bounds, filters role/status. Returns owner-only needed source/normalized fields, explicit reason codes and duplicate hints. Keep dataset/row versions and hash separate from rendered amounts. Controls must reach all rows, reset on filter changes and normalize initial URLs above the last page.
- Upload response201 `{batch, files, reconciliation}`; read rows ordinary Laravel paginator. Standard422 malformed input/mapping,409 stale/conflicting intent,403 authorization/feature/transport,404 batch not found,419 CSRF. `errors` identify role/line/field + safe reason, not copied source records. Unsupported/oversize transport must also have private error headers.
- `DiscardHoneyBookImport::execute(User,int batchId,array $input,string $key): ImportBatch`; `POST /admin/api/imports/honeybook/{batch}/discard`, expected_version + UUID. No discard of committed domain evidence; A has no commits. Revoke stage access, purge private files/uncommitted payloads, retain only non-PII hashes/counts/audit tombstone. Filesystem cleanup runs through explicit retryable cleanup state; replay never restores data. No forced delete of an unrelated filesystem path. Metadata/receipt/audit updates are atomic; filesystem effects are honestly tracked separately.

## B/C obligations before enabling domain commit

A preview hash is evidence of reviewed data, not a reservation or payment. B's additional contract will require locked batch/row/source hashes + customer/source event/resource versions, an explicit existing/new customer choice, service/characters/outfits mapping and original source money/evidence. One HoneyBook project gets one durable CRM linkage under a unique key and row locks. Fresh replay returns its original linkage; changed source only reconciles eligible drafts, never overwrites confirmed/signed/paid records.

Historical money must carry **HoneyBook-imported provenance** and owner-reviewed source evidence; it must not be inserted into today's `environment=test` Stripe/Zelle ledger as newly verified funds. Missing transaction dates or breakdowns stay unknown. Existing finance/capacity paths need an explicit audited imported-agreement bridge before they can consume this money; no fabricated payment reference/date, deposit exception or current catalog total. Client payment/contract/grant/message creation stays blocked for unreconciled imported projects. Existing HoneyBook contract references remain source references, not CRM signatures.

C must reserve actual staff/costume/equipment/transport capacity through the same availability rules, allowing concurrent conflicts to fail without erasing imported money. Cutover report compares the complete declared future-confirmed source set against actual imported/project-linked/resource-confirmed events; any unmapped, conflicting, unreserved or unaccounted source row blocks an all-clear. The system cannot prove complete HoneyBook export coverage from a partial CSV; owner confirms export scope/date only against a concrete reconciliation report. No blanket `all_imported=true`, fake occupied capacity or public availability activation in A.
