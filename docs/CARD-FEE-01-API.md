# CARD-FEE-01 · standard portal monetary backend · 2026-10-28

Owner-approved3% applies to credit cards only. Integer cents: fee=round-half-up(principal*3/100), gross=principal+fee, bounded by Stripe's99,999,999-cent limit. Never gross up by dividing by0.97. Freeze terms on each new intent; existing intents retain their original terms, including legacy0fee checkouts. Principal alone reduces the party balance. Actual fee gets a separate customer_fee ledger row atomically with the principal receipt, with independent deduplicated identity; source/intent/amount/currency/payment verification and reconciliation remain required.

Delivery is default-OFF `WAOO_REGULAR_CARD_FEE_ENABLED=false`. Enabling also requires an externally verified **credit-only** provider policy for the exact configured test account (`WAOO_STRIPE_CREDIT_ONLY_ACCOUNT`), not just payment_method_types=card (which also accepts debit/prepaid). This is an operator attestation of actual provider enforcement/network compliance, not an API-created rule or a funding selector supplied by the browser. No provider configuration is changed here. New-fee receipts independently require retrieved charge funding=credit; missing/debit/prepaid proof is quarantined for reconciliation, never credited as if the policy succeeded. Preserve authenticated webhook evidence, do not fabricate a receipt or automatic refund.

Portal DTO exposes exact numeric terms and formatted card_principal/card_fee/card_total plus a server-derived card_quote_sha256. A portal checkout under the new policy must acknowledge the current hash; stale or missing acknowledgment fails before creating a provider request. Hash is a stale-price binding, not human consent or a secret. Server recomputes all amounts; no caller fee/price is authoritative. Owner-created sandbox intents use the same arithmetic. Feature enablement requires Claude's reviewed UI/approved ES+EN disclosure and actual provider policy verification; no fee is silently enabled against today's unchanged credit/debit page.

No existing client wording/config/client-texts.php, legal terms, TIP/QuickStripe money policy, or production flag changes. HTML layout/disclosure is Claude's next piece; this provides its monetary contract and disables unsupported activation. All sends remain independently held.
