Existing actual amount/reference/explicit-offset received_at/verified_received and UUID remain mandatory. received_at must be at/after effective time and not future. The owner confirms this is genuinely new money received after the switch, not verification of an amount already included in HoneyBook. Native callers omit these fields. No browser source total/paid/balance inputs.

Under the existing event lock, revalidate effective authority/current binding and exact-key receipts with current reads. Source Zelle records its normal owner verification audit, then an immutable allocation in the **same transaction**; failure rolls back both.
