Independent `waoo.sandbox_cutover_bridge` / `WAOO_SANDBOX_CUTOVER_BRIDGE` defaults OFF in addition to C3 A's imports+cutover gates. Owner active+2FA, staging HTTPS/secure cookie, CSRF writes and private no-store. Reuse CutoverCohort's actor→import singleton→sorted portal grants→events→import links protocol. Never accept a browser-selected event subset, source amount or effective time.

`PrepareCutoverOpeningAgreements::execute(User $actor,array $input,string $key):array`, POST `/admin/api/cutover/openings` with `{reconciliation_id,expected_cohort_sha256}` + UUID Idempotency-Key. Require a cryptographically intact, unexpired prepared C3 A reconciliation whose hash equals the **complete current** source/document/contact/capacity/collection/scope snapshot; all C3 A prerequisites must still hold. Original retirement attestations are not remote actions: while HoneyBook remains active keep them false and this preparation remains unavailable. Owner must not disable anything to satisfy this development feature.

Atomically prepare one immutable opening set per reconciliation and one encrypted opening per server-selected event. Same current reconciliation under another key reuses the set. Same-key replay verifies stored set integrity and returns historical metadata, never refreshes source observation/expiry or implies current authority. Changed body409. Late cohort member, contact/source/resource/version drift, missing original, uncertain collection/mail/TIP outcome or exact240min expiry refuses new preparation. Audit/receipt failure rolls back every member/set. No partial group.

Response `{opening_set_id,reconciliation_id,cohort_sha256,event_count,source_observed_at,expires_at,authority:preparation_only,effective_at:null,transfer_available:false,sending_enabled:false}`. No private evidence/client fields or ciphertext. Presence of a prepared set never removes C3 A's overall transfer blocker; native guard adapters/atomic activation remain separate.

Current requires intact matching latest source snapshot/reconciliation and future expiry. `current` means preparation current, never collection authority. Owner notes, original source text, signed PDF bytes, review references and staff details never in projection. No public/client/staff opening route.

## Persistence and bridge boundary

Migration460000 reserves450000 for unfinished history B1. Immutable `cutover_opening_sets`: reconciliation unique FK, cohort/payload hashes, encrypted manifest of all event/source fact hashes, author, actual original source observation+expiry. Immutable `cutover_opening_agreements`: set/event/import-link/source-revision FKs, unique(set,event), encrypted source opening facts bound to set/reconciliation/event/customer/review/capacity/document metadata, SHA. No active/effective field that can be flipped to bypass a future atomic activation. Populated down refuses deletion; empty roundtrip supported.

Freeze original agreed total and source commercial discrepancy provenance, gross positive source receipts, negative adjustments/refunds, net and raw balance/credit; preserve signed flag separately from the owner-attested original. Bind actual operating event version and original imported capacity evidence/deposit-review hash, not a fictional event.version-1 FinancialRevision. Retain only IDs/hashes for private notes/operational review in the opening payload; original encrypted evidence remains authoritative. Original source date-only due day is separate from explicit owner-reviewed CRM due instant; fully paid can have neither. Source funds stay unverified, with no bank timestamp. Set expiry is the original reconciliation expiry; opening creation/replay cannot renew it.

`OpeningBalance::calculate(array $opening,array $movements=[]):array` is an **internal arithmetic helper**, not a payment/receipt API or proof of verification. Closed opening input `{original_total_cents,source_gross_received_cents,source_refund_cents,source_net_received_cents}` must be nonnegative integers with gross-refunds=net. Closed movement input list `{kind:receipt|refund,amount_cents:positive int}` is synthetic until a later verified allocation adapter supplies it. Bounds100000000000 cents/source and10000 movements; fail on malformed input/overflow, never round/convert. Compute opening source net + new receipts - new refunds, raw total minus net, nonnegative balance/credit, distinct source vs CRM totals and origin classification. No TIP inputs permitted. Preparation projections always pass an empty movement list and report0 new CRM cash/new sales. Existing reports continue excluding imported confirmations/source cash; prepared openings cannot become a new sale by their creation date.

**Still required for C3 B completion:** effective opening/verified post-cutover allocation seam, common agreement/capacity authorization in native Finance/MAIL/TIP without weakening native event-version checks, owner/client collection projection and scoped original-document access, report forecast adapters. Then a separately reviewed C3 action can activate the complete group atomically and define reversal.
